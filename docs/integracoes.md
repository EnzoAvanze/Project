# Integrações e limitações

| Recurso                  | Implementação disponível                                                                                               | Configuração/evolução pendente                                                                                                                         |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Identidade               | Contas locais, scrypt, sessão HttpOnly de 7 dias, convites com expiração                                               | HTTPS e `COOKIE_SECURE=true` em produção; revisão de recuperação e proteção contra abuso                                                               |
| Biometria                | Não é exibido um botão falso                                                                                           | Implementar WebAuthn ou biometria nativa, credenciais por dispositivo e recuperação segura                                                             |
| Recuperação de senha     | Rota responde 501 e informa que não enviou e-mail                                                                      | Serviço transacional, token de uso único com hash/expiração e rate limiting específico                                                                 |
| Avisos internos          | Persistidos em `notifications`, consultados a cada 10 s; leitura por usuário                                           | Não comprovam que alguém viu, exceto recebimento SOS explícito                                                                                         |
| Lembretes                | Agendador de 30 s enquanto servidor ativo; horários civis em São Paulo; deduplicação por dose/dia; adiamento de 15 min | Não são alarmes garantidos; processo desligado não executa lembretes                                                                                   |
| Notificação do navegador | Pedido explícito de permissão; tentativa de Notification para avisos recentes enquanto a página está aberta            | Não há confirmação de entrega/visualização; alguns navegadores/WebViews só permitem push via service worker                                            |
| Push de fundo            | Não implementado                                                                                                       | FCM/APNs/Web Push, credenciais seguras, consentimento, filas, retries e recibos do provedor/dispositivo; adicionar assinaturas por usuário/dispositivo |
| SOS                      | Confirmação, gravação idempotente, aviso interno e recebimento pelo cuidador                                           | Push/SMS/ligação externa não configurados. Registrar não significa enviar push nem receber atendimento                                                 |
| Ligação                  | `tel:` no web e Linking no invólucro mobile                                                                            | Depende do discador e telefonia do dispositivo. Não há confirmação de chamada concluída                                                                |
| Agenda                   | Download .ics no cliente web                                                                                           | O usuário importa no calendário. Integração nativa depende de permissão; downloads em WebView precisam de validação física                             |
| Voz                      | Web Speech API quando disponível; reconhecimento preenche o campo, usuário envia; síntese lê a resposta                | Reconhecimento pode usar serviços do navegador. Não há suporte garantido offline/WebView; APIs nativas ainda não integradas                            |
| Assistente               | Regras determinísticas sobre dados autorizados do paciente; conversa persistida                                        | Sem LLM. Para integrar IA, configurar provedor, escopo, minimização de dados e limites clínicos antes de compartilhar informações                      |
| Relógio                  | Protótipo web com interface própria, API compartilhada e fila offline                                                  | Wear OS/watchOS, Bluetooth, vibração e push nativos exigem SDKs, assinatura e hardware. Não há localização                                             |
| Mobile                   | PWA funcional e contêiner Expo/React Native com WebView e mesma API                                                    | Sem APK/IPA validado; compilar e testar com Android SDK/Xcode. Não é uma interface React Native reescrita                                              |
| Armazenamento            | SQLite relacional local, FK/índices/transações; fila IndexedDB no cliente                                              | Sem cifra em repouso na implementação. Use disco/backups cifrados e migre para PostgreSQL conforme escala                                              |
| Offline                  | Confirmações explícitas de dose, SOS e dor são enfileiradas; reenvio idempotente e conflitos 409                       | Não transmite SOS sem internet. Não há background sync com página fechada. Os dados da API não ficam em cache offline                                  |
| Som/vibração             | Feedback visual e leitura opcional em voz alta                                                                         | Tons/haptics nativos não implementados; configurar por plataforma e testar em hardware                                                                 |

## Estados de entrega

- **Lembrete programado**: medicamento/consulta cadastrado no banco.
- **Aviso interno disponível**: registro criado no servidor para a rede autorizada.
- **Pendente no aparelho**: ação guardada em IndexedDB sem confirmação do servidor.
- **Visualizado pelo cuidador**: cuidador autorizado clicou explicitamente em confirmar recebimento do SOS.
- **Envio/entrega externos**: nenhum provedor está configurado. O campo `external_status` permanece `not_configured`, nunca `sent` ou `delivered` inventados.

Para adicionar um provedor real, mantenha uma outbox no servidor com identificador idempotente, destinatários vinculados, preferências e estados `queued`, `sent`, `delivered`, `failed`. Separe recibos do provedor de ações do cuidador e não registre payloads clínicos em logs. Declare credenciais apenas no gerenciador seguro da implantação. Não existem credenciais reais no repositório.
